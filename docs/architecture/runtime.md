# Orbit 运行架构与安全边界

Orbit 是 Panel 的桌面客户端及本地接入协调器。Panel 决定账户权限、节点/模型目录和结算；
Edge 执行模型请求。Orbit 管理桌面授权、本地配置、Claude 转发、图片文件及只读用量投影。
本文描述当前源码职责，不作为应用已加载配置、真实上游成功或发布验收的证据。

## 进程与模块职责

| 层                | 职责与入口                                                                                                                                                           |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Vue / Pinia UI    | 展示原生元数据、收集选择和确认，通过[typed bridge](../../src/shared/bridge.ts)调用命令；明文只进入主动揭示的临时组件状态，不进入 Pinia 或事件，不直接访问 Panel/Edge |
| Tauri 桌面壳      | [commands](../../src-tauri/src/commands.rs)提供闭合 IPC、原生文件选择/剪贴板和更新动作；[应用入口](../../src-tauri/src/lib.rs)组装 Service、事件、窗口及单实例       |
| orbit-core        | [Service](../../crates/orbit-core/src/service.rs)协调账户作用域、网络、vault、store、配置事务及图片任务，返回[公开 DTO](../../crates/orbit-core/src/dto.rs)          |
| credential helper | [独立可执行文件](../../crates/orbit-helper/src/main.rs)只接受客户端类型和 opaque binding UUID，从固定部署位置定位只读 store，再按冻结授权读取凭据或本地映射 token    |

主窗口 capability 仅开放声明的 Orbit 命令；CSP 将前端网络限制为 IPC 和本地图片预览。
`orbit://state`、授权、错误、图片输入及下载进度事件用于刷新视图；UI 的状态和按钮不代替
原生校验。异步操作在账户、连接 revision 或授权 epoch 改变后拒绝发布旧作用域结果。

桌面构建支持 macOS arm64 与 Windows x64。启用 `system-integration` 的构建使用应用数据
目录、真实用户路径和系统 vault，并校验部署的 helper 摘要；普通隔离构建使用仓库 runtime
路径和 DeniedVault。开发 UI 或测试替身不能据此取得真实安全存储及用户配置写权限。

## Panel 桌面授权与凭据

生产 Panel origin 由[network](../../crates/orbit-core/src/network.rs)固定为
`https://orivelle.powerbyte.io`；普通 debug 构建也不开放 issuer 覆盖。其他 issuer、回环
HTTP 和测试 CA 只存在于显式编译的测试客户端。

[Installation](../../crates/orbit-core/src/identity.rs)为安装生成 Ed25519 密钥及备份加密密钥。
登录先证明 vault 可读，再启动随机端口的 `127.0.0.1` 回调监听和 PKCE S256，打开同源
Panel 授权页，由系统浏览器完成用户登录/确认。原生回调严格核对 Host、路径、state、issuer
和单次授权请求；超时、取消或被后一次登录替代的流程不能提交连接。

浏览器收到的回调结果页使用内置中文页面，适配系统明暗主题。只有换码、账户刷新及本地
连接提交完成后才显示“账户已连接”；用户拒绝和已收到的无效回调/换码失败分别显示取消
或失败，并引导返回 Orbit。页面不包含账户资料、回调参数或凭据，不加载外部资源。

换码及后续桌面 API 使用安装证明，绑定方法、目标、安装/会话、时间、nonce、request ID、
正文摘要及需要时的 Bearer 摘要。会话 access/refresh token 与推理 `orv_sk_*` 分开存放；
推理凭据经一次性 delivery ticket 领取，未知交付结果不自动重领，账户仍可保留只读访问。
节点/模型、API key 状态和权限由 Panel 刷新；客户端不从目录缓存猜测新的推理授权。

登出先推进本地授权失效状态、停用 helper binding 和 Claude 映射，再尽力撤销远端会话。
清理 vault 失败不会恢复已失效授权。helper 按 origin、安装、账户、provider、凭据 revision、
epoch、有效期和 enabled 状态逐项匹配，不跟随当前 GUI 选择切换到其他账户。

## vault、本地存储与启动恢复

[vault](../../crates/orbit-core/src/vault.rs)使用 macOS Keychain 或 Windows 原生凭据存储，
保存签名私钥、会话、推理凭据、备份密钥及 Claude 本地 token。普通 DTO 不含机密；唯一例外是主窗口主动调用的单次 Key 揭示响应，组件在关闭、失焦、切换账户或 30 秒后清空。复制响应不含密钥，最终原生剪贴板写入与登出持有同一账户锁。
helper 只有对应读取路径，Claude 映射 secret 的新建能力单独注入 GUI，不开放通用 ACL 更新。

[Store](../../crates/orbit-core/src/store.rs)使用私有应用目录和 SQLite WAL，保存连接/安装
元数据、设置、任务及文件索引。图片任务包含本地提示词等业务资料，参考图、原图和预览
保存在私有本地文件；它们不因使用 vault 而成为端到端加密数据。配置原始字节进入加密 journal。
图片路径、格式、摘要及预览请求均由原生层校验，WebView 只按当前作用域读取受控 asset。

单实例与 runtime lock 避免多个桌面进程共同改写同一目录。启动先处理更新恢复，再打开
Store 和 Service；中断的图片任务标为 `unconfirmed`，不重放网络生成。配置恢复另按已确认
journal 协调；恢复不能确认时保留冲突并阻止同客户端新应用，不擅自覆盖外部改动。

## 配置预览、应用与切回

### API Key 的本地选择与升级清理

[Key service](../../crates/orbit-core/src/service_api_keys.rs)使用固定的 api-keys-v1 授权 profile。旧会话不扩权，Key 读、明文揭示、写和使用凭据分别检查 scope。所有接口固定路径并签署 Bearer 摘要；凭据 ticket 绑定安装、会话、Key revision 和 use/reveal 用途。普通列表、详情和管理结果只有元数据。

默认 Key 的 ID/revision 和 vault 引用保存在本地 connection；Panel 无默认选择表。每次选择生成唯一 secret reference。已接入 helper、Claude 映射及图片任务保留原有冻结引用，选择新默认不改变其授权 epoch。远端权限、风险、Key revision、有效期发生变化时，先写持久化的逐引用停用标记，再撤销相关 binding 并尽力清理 vault；删除失败也不能复活旧授权。

管理请求在发送前落地同一个 operation ID、时间和完整请求；结果不明确时阻止新操作，核对时重发相同请求。Panel 在原业务写锁内把动作和审计回执一起提交，审计被清理后也拒绝超过时限的旧请求。已确认成功不因随后元数据刷新失败而再次执行。

接入页没有独立的 Key 选择，原生预览冻结 API Key 页所选默认 Key，确认前默认选择变化即失效。接入确认弹窗只列节点和密钥，取消接入仅保留简短确认；账户归属、目录、目标文件及差异继续用于原生校验。切换客户端 Key 复用既有恢复与应用事务，避免重写原始切换快照。取消 Claude 接入默认使用主设置协调模式，只显示一个取消入口。普通提示默认 4 秒、错误提示默认 6 秒关闭。

旧自动 Key 由 Panel 根据明确的 orbit_issued 关联自主清理，不等待本地 helper、快照、任务或替代 Key。定时维护和新版 bootstrap/Key 列表请求均可完成有界升级清理；删除后保留安装 tombstone。Orbit 只按服务端新状态停用相应凭据，不再发出清理确认请求。

[SystemPaths / 检测](../../crates/orbit-core/src/system.rs)核对安装身份、所需配置能力、
默认用户目录及[本地托管策略](../../crates/orbit-core/src/policy.rs)。自动配置支持
macOS arm64 与 Windows x64 的默认路径。Windows 核对 MSIX 注册身份或官方 EXE 发布者，
Claude 的 ASAR 配置能力从已签名 PE 绑定的头摘要及成员摘要核验后读取。
未知来源、目录锚点或策略不能授权写入。
配置资格不等价客户端正在运行、已读取配置或实际连通，也不依赖一个固定版本白名单放行。

Codex 与 Claude 的确认窗口在调用原生预览前打开。接入预览使用已同步的账户和模型目录，
执行本地配置检查，只在内存中保留一次性 ID、账户、安装、节点、凭据、模型、策略和生效
配置的标识，可以随时取消。前端需要同步模型版本时只读取原生缓存。用户点击确认后，
原生层联网刷新一轮账户和模型目录，核对本机和已审阅的选择，读取最新完整文件，创建
加密事务。Claude 此时分配本机端口。账户、授权、路由或客户端发生变化时需要重新检查；
确认失败且账户作用域未切换时，前端同步本地状态和已刷新的目录，再次预览使用这些缓存。

[ConfigEngine](../../crates/orbit-core/src/config.rs)用客户端锁、原子文件替换及持久
`prepared → publishing → committed/conflict` journal 协调整组文件与 helper grant。
原始字节以 XChaCha20-Poly1305 加密，关联安装、账户、客户端、策略及操作用途。
每个客户端维护独立的接入前文件快照。切回时先核对当前文件，确认后通过同一事务恢复。
恢复旧配置字节不会复活已登出、撤销或过期的 helper 授权。

Claude 取消接入默认使用 `claude_library_settings_v3`。文件内容与接入时写入的内容相符时，
逐字节恢复原文或恢复为文件不存在。有其他修改时，主配置仅恢复 `deploymentMode`，
索引移除 Orbit 新增的条目并还原 `appliedId`，保留其他条目和原始 JSON 值。
源快照、当前整组文件和派生结果均受认证。活动配置被切换、Orbit 自身条目或 profile 发生变化，
或预览恢复后文件又被编辑时，整组停止。旧的严格恢复及 V1、V2 协调按原语义校验。

Windows 使用本地磁盘句柄、文件 ID 与原生 ACL 检查目录锚点，拒绝重解析点和非受信写权限。
完整预览和提交重新验证安装签名及配置能力；轻量状态缓存不能授权写入。安装范围身份允许
同一官方 MSIX 家族或 Squirrel 安装根下的兼容更新，更新仍会使进行中的预览失效。
Windows 初始化和 bootstrap 的本地 I/O 在后台执行，主窗口不等待探测完成才处理消息。

Codex 的「确认接入」窗口打开后才请求原生检查。待确认草稿保存在内存中，绑定所选账户、节点、凭据、目录、策略、客户端以及当前配置路由。窗口没有点击时限。提交时重新获取账户和目录，验证作用域后才准备 helper 绑定及文件事务，关闭窗口会丢弃草稿。Windows 在一次同步原生操作内持有安装文件句柄并复用验签结果，跨网络等待和用户操作时重新验证。

## Codex 与 Claude 的本地链路

Codex 配置与模型目录通过同一事务发布：[catalog binding](../../crates/orbit-core/src/codex_binding.rs)
将当前账户/节点允许的模型声明与包内受控模板结合，保留推理权限交集，并确定默认模型。
配置只写入节点地址、目录及 helper 引用；Codex 调用 helper 取得绑定凭据后直接访问 Edge。
目录声明、配置已保存和 `restart_required` 状态均不证明 Codex 已加载或上游请求成功。

接入状态另由 `client_process` 与 `service_activation` 管理。原生后台每两秒读取当前用户的应用进程路径和启动时间，按实际选用的 helper、配置路由及文件保存时间建立持久记录；旧记录缺失时从当前接入文件迁移。旧实例或相关后台进程仍在时为「待重启」，没有新的桌面实例时为「待启动」，所有相关实例均在配置保存后启动且绑定仍有效时为「已连接」。macOS 使用 libproc，Windows 使用进程快照、进程映像路径/创建时间和桌面窗口 PID，避免把同名程序或独立 CLI 当作桌面重启。Orbit 重启后恢复检查，隐藏窗口后继续运行；配置路由更新会重新等待启动，用户偏好修改不会重置既有记录。Claude 的映射服务也须在运行。此状态不填充 `loaded_evidence` 或 `connection_evidence`，不读取 Vault、不发送验证推理请求，也不授权任何配置或凭据操作。

模板身份与实际调用 ID 分开：目录 `slug` 保留 Panel 的调用别名，`display_name` 使用平台显示名；可打印 ASCII 别名允许 `/`、`:`、`@` 等字符。Panel 可为已知上游自动投影模板，也可显式声明别名的模板，Orbit 不按别名猜上游。推理能力未知时保持不可用；上游默认档位为空时，Orbit 按当前权限与模板的交集选取并明确写入本地默认值，多代理档位也不得越界。自动选择没有合格候选时分别报告声明、推理或 ID 问题。

原生进程在启动时与此后每五分钟刷新活动账户和节点目录，窗口隐藏后继续轮询。手动刷新复用同一入口。已确认的 Codex 接入可在原节点和已绑定 Key 下更新目录，保留仍可用的默认模型。路由冲突、作用域变化、未知能力或断网会停止覆盖。

Codex 适配器解析根配置和所选 profile，只修改根路由字段、活动 profile 中已有的同名覆盖以及 Orbit 专用供应商。名称被占用时分配空闲名称。已提交的快照保留两个目标文件的完整原始字节。确认、目录同步和恢复时比较实际生效的路由和专用目录，再以刚读取的整文件字节作为原子发布的前置条件。同步提交会同时保存接入以来的非路由修改和最初文件备份。切回时无外部改动即可恢复原始字节，有兼容改动则只撤销 Orbit 管理的字段。部分发布继续使用既有事务恢复。

前端按用户动作反馈：顶部「刷新数据」只报告所请求数据的读取成功或失败，不把目录编译或保存状态当作刷新提示。启动与周期同步成功保持静默，短暂网络错误和用户切换其他平台造成的配置差异不弹同步通知。后台只有缺少模板/推理声明、无兼容候选或不支持的模型 ID 导致整个已接入目录不可生成时，才使用对应的可处理原因提醒；按账户/连接与原因去重。刷新过程中的状态事件不插入此类通知，接入与切回沿用各自确认结果。

Claude 的配置库、活动索引和必要主设置由[Claude 协调器](../../crates/orbit-core/src/service_claude.rs)
一起处理。当前接入要求分别选择 Sonnet/Opus/Haiku 模型，显示文字直接使用所选模型名称，实际请求
使用所选模型 ID；这三个入口不是失败时换模型的调度策略。新映射按 v4 冻结名称快照，旧 v1–v3
配置保持原有校验与恢复语义；重新接入后更新显示名称。接入页始终保留三个模型选择框，已接入时使用当前账户和 Panel 下的已确认绑定，只禁用编辑。绑定模型不在当前目录时仍显示其 ID，不替换成其他可用模型；未完成选择的说明紧邻接入按钮。

[mapping manager](../../crates/orbit-core/src/claude_mapping.rs)为绑定保留固定 loopback
端口及专属本地 token。helper 向 Claude 提供本地 token；[HTTP 映射](../../crates/orbit-core/src/claude_mapping_http.rs)
只接收固定模型目录/Messages 路由，核对 Host、Bearer、别名及当前授权，拒绝浏览器来源头、
任意目标和升级连接。core 替换模型并携带真实推理凭据访问既定 HTTPS Edge，流式返回结果。
每次转发有有界并发/体积/期限和原生 permit；不跟随重定向、不自动重试已发送请求，不开放
通用代理。Orbit 必须持续运行；重启后只为经重新核验的当前活动配置恢复映射。

Windows 映射 token 使用 Credential Manager 的用户作用域存储。新建绑定入口仅由 GUI
注入，并锁定私有目录、helper 摘要及协作锁后检查不存在与写后回读；helper 不具备创建入口。
这些检查不构成 Windows 同一用户内的应用隔离，不能将其描述为 Keychain 的应用 ACL。

## 图片任务与平台用量

[图片模块](../../crates/orbit-core/src/images.rs)限制格式、尺寸、解码内存、提示词、请求/
响应体和本地磁盘预算。创建任务冻结账户/连接、节点、模型及输入摘要；发送前再检查当前
授权，只向选定 Edge 的 Images generation/edit 端点发送一次。订阅控制保留每次一张结果、
最多五张参考图及不透明/透明背景。单独的 `image_api_parameters` 目录声明 API 高级能力，
不扩宽 `image_parameters` 的订阅范围；旧 Panel 或未知协议不显示这些高级控制。
`images_api` 按本次实际参数选用 API 协议，显式默认值仍留在订阅路径；mask/markup
冻结为当前连接作用域的 PNG 素材并校验首张参考图尺寸。高级请求的销售价格和专用池
选择仍由 Panel/Edge 决定，Orbit 显示费用路径与本次调整参数对应的错误，不代算价格。

`images_stream` 在有界 SSE 中读取生成/编辑事件，临时 PNG 预览只对当前连接可见，
不会写入本地历史或暴露保存按钮。仅在完整终态数量与请求一致后进入原有本地保存事务。
`image_media` 使用固定版本的 resvg/quick-xml 和 GIF 解码器，校验 SVG 脚本、事件、外部引用、
XML 深度、节点、嵌入位图及离屏图层预算，禁用文件资源解析；原 SVG 仅用于完整校验后的保存，
WebView 只取得 PNG 渲染图。GIF 在有界逐帧解码后生成最多 768 边长的动图预览，保留帧时序
与循环信息，最多十六帧；剪贴板取首帧。预览协议只为当前账户的已保存 GIF 开放 `.gif`，
不将原文件路径交给 WebView，删除历史同时清理 PNG/GIF 缓存。原文件仍按摘要校验和原字节保存。
SVG/GIF 不作为编辑参考图；接收和复制沿用既有内存 worker、账户、epoch 与导出归属检查。

提交前可取消排队；提交后的取消、超时、网络故障或进程退出保留结果待确认，不能推断
上游已撤销或免计费。收到图片后先暂存再提交本地历史；`retry_local_save`只保存已有结果，
不重新生成。已取得 Request ID 的任务可以通过 Panel 只读记录核对执行/费用，不凭空补图。
复制和另存先冻结文件摘要，最终写入时重查账户、epoch 和历史归属。

[用量服务](../../crates/orbit-core/src/service_usage.rs)用桌面会话及安装证明读取 Panel 汇总
和分页记录，覆盖该账户全部平台入口；只读账户不需要推理凭据或已选节点。查询和返回时
均检查当前连接/revision；金额保持十进制字符串及币种，未知、待确认和历史语义原样保留，
Orbit 不计算平台价格、余额、预算或结算，也不以本地图片历史替代服务端账务。

## 更新与桌面生命周期

[更新模块](../../crates/orbit-core/src/updates.rs)只有编译入审核过的渠道/公钥才启用应用内
更新，支持 macOS arm64 和 Windows x64 的正式构建。下载与安装分别确认；候选须匹配平台、更高版本、
签名版本及归档边界，下载 URL/重定向限于固定渠道规则，不能由 WebView 或设置提供信任根。

安装进入 maintenance，排除在途任务、配置操作与授权，并独占 helper 更新锁。
未确认的 `prepared` 配置预览尚未写入客户端文件，保留或过期都不阻止更新，也不会因更新而删除。
`publishing`、`conflict` 及未知配置状态仍阻止安装；真实配置写入在持久化 `publishing` 后才开始。
安装失败原因保留在设置页和确认窗口中，用户处理后可重试已验证的下载包。
[macOS 恢复事务](../../crates/orbit-core/src/update_recovery.rs)封存旧包/数据库基线，替换应用后
重启；下次启动在暴露 Service 前验证并提交数据，失败按 journal 恢复旧包和受控数据状态。
恢复后要求重启或发现篡改冲突时，不继续用已映射的新二进制提供普通服务；不借数据库回退
恢复旧凭据有效性，也不回放模型请求。

Windows 的 [NSIS 交接](../../crates/orbit-core/src/update_windows.rs)重新核对本地包摘要和版本签名，
只从已安装的 NSIS 程序交接到原目录。私有暂存包和当前 EXE 由句柄禁止写入/替换，成功启动
passive/update/restart 安装器后才退出，NSIS 更新并重新启动应用；启动失败则保持当前应用可用。
新进程沿现有启动路径重新部署内嵌 helper、清除维护标记。Windows 使用 NSIS 的安装和错误处理。

[窗口/托盘生命周期](../../src-tauri/src/desktop.rs)与 Service 分离：默认关闭窗口只收起，
后台图片任务和 Claude 映射继续；真正退出停止映射，未确认图片按上述状态保留。
设置可将关闭改为退出，存在任务、未保存结果或转发时提示影响；托盘不可用时保留窗口入口。
再次启动唤回已有实例。普通网络、错误及[诊断导出](../../crates/orbit-core/src/service.rs)
只公开受控状态，原始网络错误/凭据不直接进入 UI 或导出；用户须先预览再选择保存诊断。
