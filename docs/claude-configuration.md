# Claude Desktop 本地配置合同

本阶段补齐 Claude 的整组保存与恢复。本文的文件合同来自官方文档及固定安装包的只读核查；它不证明配置已被真实客户端载入，也不证明 Code 请求兼容或连接成功。

正常 Service 入口已接通精确三文件预览、明确确认、保存、重开协调与逆序恢复，使用认证的 v3 Claude 上下文和原 profile 依赖检查。项目内隔离往返测试已比较实际保存、重开和恢复后的文件字节；这些测试使用合成配置和 MemoryVault，没有操作真实 Claude 用户配置或系统安全存储。

## 固定版本与文件

当前自动写入合同限定为 macOS arm64 的 Claude Desktop `4.4212.0`，bundle ID 为 `com.anthropic.claudefordesktop`；此前 `2.19675.0` 候选的静态证据不能代替该版本验收。其他版本、非默认数据目录和 Windows 目标在取得对应合同前保持未核验。

[官方配置说明](https://claude.com/docs/third-party/claude-desktop/configuration)规定本地配置库及当前配置索引；[安装说明](https://claude.com/docs/third-party/claude-desktop/installation)要求应用配置后重启。固定安装包进一步确认同一 `~/Library/Application Support/Claude-3p` 根下的三份文件：

| 顺序 | 相对路径                       | 本次负责的内容                                            |
| ---- | ------------------------------ | --------------------------------------------------------- |
| 1    | `configLibrary/<新 UUID>.json` | 新建 Orivelle profile，正文为扁平配置键对象               |
| 2    | `configLibrary/_meta.json`     | 保留既有 entries 和未知字段，追加新条目并选择其 appliedId |
| 3    | `claude_desktop_config.json`   | 仅将 deploymentMode 设为 3p，保留其他字段                 |

新 UUID 不能覆盖既有文件。官方 V2 导入格式的嵌套正文不等于本地 profile 格式，不能直接写入配置库。固定公共代码仅用来核对读取和写入行为，不复制第三方实现。

新 profile 基于当前本地选择：精确替换已知的推理连接、凭据和模型字段，保留可确认不承载秘密的其他设置，旧 profile 字节不变。当前 profile 含未知、无法分类或其他承载秘密的设置时，整体拒绝自动切换，不丢弃字段或将它们复制到新文件。只有 metadata 原本不存在才按首次配置处理；索引损坏或已选文件缺失不能回退为空配置。metadata 和模式文件的其他字段在原文件范围内保留。

固定版本的 `coworkEgressAllowedHosts` 可以在严格校验后原样保留：仅接受有界的主机模式字符串数组，不新增、合并或规范化主机；既有 `*` 也只按原值保留。URL、用户信息、控制字符、类型错误和超限内容仍拒绝迁移。Orbit 不生成出口白名单或隐藏模式选择设置，也不改变旧 profile；既有可迁移设置及原权限范围随原配置保留。

本次核对的公开安装材料为 Info.plist SHA-256 `7ff3c89ba08993679d13e2b5d3b3f6de331233901aa069ae83591a5168e42344`；64,685,328 字节 ASAR 的 SHA-256 为 `0f8f7d420223874fbcfc8de8e29a978d0a04bb2ae620d4b454dc3714f275035c`；其中 `.vite/build/index.chunk-m4oMImJ-.js` 的 6,780,508 字节正文 SHA-256 为 `926694919e5ff5d05cb804945637ffbe6ae75bdeac5e461f30e7c3d5fa043ccb`。这些是已安装版本的静态合同证据，不是稳定公共 schema 的承诺。

`4.4212.0` 在普通启动时会遍历配置库，将旧明文秘密字段封装为系统安全存储密文，并可能移除主配置中的旧 `enterpriseConfig`。自动应用前须确认整个配置库没有待迁移内容，包含未选中和孤立的 profile；完整资格及后续写入、恢复门禁均复核，轻量卡片提示不执行全库扫描。检查只判断迁移状态，不解密或改写原配置。发现待迁移状态时显示 `claude_native_migration_required`；应先由 Claude 正常完成迁移并退出，再重新建立配置基线和预览。不能在启动会改变旧源字节的情况下承诺恢复旧基线，也不能通过覆盖迁移结果来消除冲突。

## 本地选择与管理来源

metadata 中出现任何 hybridPointer 时均阻止自动切换，包括空值或无效值。有效指针优先于 appliedId；本阶段不删除它来绕过原组织选择。当前选中 profile 使用 bootstrap 来源时同样阻止切换，其他未选中 profile 原样保留。

设备策略的完整覆盖、安装材料、默认根目录及本地选择必须分别核对。既有四个 forced-key 的局部检查不足以证明没有管理配置。无法读取、未知管理键、来源变化或覆盖不完整均阻止写入。全局 managed 与本地写入资格分开：远端组织状态仍可为 unknown；它不提供加载或连接证据。

该版本的本地管理观测覆盖 machine 和当前用户两处官方 MDM plist，并逐项检查 207 个规范键和兼容旧名的 forced 状态：保留旧版 182 项，并补齐当前公开 schema 新增的 25 项；不请求这些偏好值或凭据。静态键清单本身不提供写入权限，仍需已安装目标收据和操作上下文。完整目标每次重新验签；只有大材料的哈希可按完整文件身份复用，材料变化后重新流式计算，不能据此跳过当前签名检查。根目录作用域绑定稳定的用户祖先目录，排除本次生成文件及目录修改时间，避免自身发布导致资格失效。

卡片中的可预览提示只是轻量观测，不能替代完整写入资格。完整观测失败保留安全错误原因；Claude 验签子进程超时单独报告，真正不合格仍拒绝，不读取或输出子进程诊断内容。真实预览和发布分别复现 3 秒、10 秒上限超时，Claude 专用验签等待上限调整为 30 秒；签名要求、超时终止与回收、共享命令预算保持原有边界。签名、固定材料、本地策略及写入边界继续逐项复核，不能用超时分类代替资格通过。

Engine 的策略回调只负责重新观察本地策略及安装提示的变化，不能生成完整目标收据或授予写入权限。发布入口及上下文检查仍取得完整资格；客户端文件变更、授权启用及安全存储返回后的既有上下文复核继续保留，避免由策略回调重复执行同一完整验签。

保留官方模式选择、原登录资料和其他应用设置。将 deploymentMode 改为 3p 是明确展示的切换效果，作用于整个 Claude Desktop，包括 Chat、Code 与 Cowork；不能承诺仅修改 Code 的路由。

## 凭据、确认与恢复

新 profile 使用 [官方 credential helper](https://claude.com/docs/third-party/claude-desktop/credential-helper)，不写明文 key。helper 参数仅包含客户端与本安装绑定标识，不能携带秘密。配置中明确使用 Panel 授予的节点和模型；保存不自动发起推理请求。

新配置将 helper 执行预算设为 60 秒，与固定 `4.4212.0` 的官方默认值一致；该合同允许的上限为 600 秒。Desktop 在会话中的静默刷新仍有 20 秒内部上限，TTL、刷新开关、权限和重试行为保持原样。首次真实 Code 报告的 6 秒超时仍保留原始记录，调整预算不构成其根因已确认的证明。

历史 5 秒 journal 保持原加密内容和上下文序列化。持久化操作在执行或恢复前先认证；首次 prepare 使用 Service 生成并冻结的受信输入，同样保留严格的路径、上下文和权限检查。共享重建只尝试有限的 60 秒与旧 5 秒编译结果，并继续要求三文件完整摘要精确一致；新预览固定使用 60 秒，没有可由界面选择的旧预算入口。

Claude 的远端推理目标使用 Panel 提供的 claude_base_url；Codex 使用 connection_url。前者是自动追加 `/v1/messages` 的节点根地址，不能混用后者的 `/v1` 地址。直连时将该 HTTPS 地址写入 profile；需要本地角色映射时，profile 使用下述环回入口，受认证上下文仍绑定同一获准 HTTPS 节点。

预览读取客户端配置并生成脱敏差异，不写客户端文件、不创建客户端目录、不启用 helper。完整纯合并和资格检查通过后才准备禁用的绑定及加密 journal；旧配置中的秘密和未知 metadata、模式文件值不会进入预览。用户确认后，受认证的操作上下文绑定账户、Panel origin、安装、连接和授权版本、凭据引用、节点、模型、目标、策略及精确文件组。每次实际写入及启用授权前复查；三份文件全部读回成功后才启用新 helper。

缺失的默认配置目录仅在确认后的受锁定流程内以 0700 创建。应用按 profile、metadata、模式文件的顺序进行；恢复按模式文件、metadata、profile 的相反顺序还原。恢复删除本次新增文件后，空目录可以保留。

沿用加密 journal 和备份。中断后按整组协调；任何文件出现第三方状态时停止整组覆盖。恢复原字节与恢复授权分别判断，退出、撤销、过期或遗忘的旧授权不得被恢复动作复活。没有全局原子事务；不遵守锁的外部写入仍可能与最后检查、替换竞争。

恢复操作同时认证原 journal 的不可变内容和阶段；在安全存储返回后及后续写入边界重读，原记录删除或变化时停止。已提交操作重新进入时也须读回全部最终文件。缺失的旧、新绑定不妨碍原配置字节恢复，恢复过程不会重新创建它们；有效旧绑定也须以最新时间、授权版本及当前记录复核后才可启用。

恢复原文件不要求当前账户仍登录，也不要求原 key、节点缓存或 helper 仍可用；安装归属、目标和本地策略仍须合格。Service 重开时区分保存和恢复操作，成功恢复不会被标记成新配置已保存。

默认恢复继续逐文件比较保存后的完整字节。Claude 正常使用后写入 `preferences`，也会触发停止覆盖；不会自动切换为合并。备份行另提供“保留偏好后预览恢复”，仅处理已提交且未到期的 Claude 备份，原主配置必须存在。该入口保留当前偏好，只把 `deploymentMode` 恢复为备份中的原值或缺省状态；配置库索引和本次新 profile 仍按原字节恢复或删除。

协调要求主配置的完整顶层键集合及每个原始值在排除 `preferences` 后，与保存结果完全一致；其他字段增删或原始值变化仍拒绝。顶层重复键拒绝，偏好仅接受缺省或对象；偏好原始 JSON 保留，大整数、浮点和未知内容不经过数值转换。profile、metadata、原活动 profile、已安装目标与本地策略仍须通过既有严格检查。该能力不协调配置库、其他接入字段或原文件缺失等情况。

协调预览明确显示保留偏好和撤销接入的范围，只有用户再次确认才写入。原主配置输入保存在恢复操作的私有加密证明中，原 journal 的密文与 nonce、Claude 上下文和三文件摘要不被改写；源 journal 的阶段会按正常恢复流程更新。使用原输入重建校验，再验证确定的协调输出。预览冻结完整当前字节与目标字节，后续再写一次偏好也会使其失效；中断恢复继续使用同一加密快照。界面与 IPC 只传备份、固定协调模式或预览标识，不接受调用者提供路径、JSON 内容或任意字段选择。

macOS 文件发布沿用 0600 保护权限，本轮协调不增加原文件权限恢复能力。此前真实测试中 metadata 的原权限补回仍是单独的受限步骤。

Claude 保存或恢复失败后，界面停用这次确认并刷新本地状态，以显示部分写入对应的可恢复备份，不自动重试写入。刷新期间产生的新通知继续保留；账户或连接作用域变化时，模型目录仍按既有流程重新读取。恢复预览和确认在后台执行，避免完整资格检查阻塞界面。

保存成功只报告配置已保存；严格恢复报告原字节已恢复，偏好协调仅报告接入配置已恢复、后续偏好已保留。两者均需重启，载入与连接仍未确认。实际加载、模型选择、Code 主辅模型、流式、工具和错误处理仍需独立真实客户端验收。

## 本地模型角色映射

正式 `4.4212.0` 的真实 Code 界面已将所选 `gpt-6-luna` 从模型列表移除。对于需要角色适配的获准模型，Orbit 使用最小本机映射：Sonnet、Opus、Haiku 是客户端技术角色，全部请求都转到本次选择的同一实际模型。`labelOverride` 和预览显示真实模型 ID 与角色用途；这些名称不表示上游变成 Claude，也不承诺模型能力等价。配置不额外启用 1M、Fast、tier 或 reasoning 选项。权限、预算、价格和最终结算仍由 Panel 按实际模型决定。

映射仅绑定 `127.0.0.1` 的本机端口，入口包含该 binding 的 UUID。它只提供认证后的模型目录与 Messages；Messages 允许无 query 或单个 `beta=true`，不提供任意目标、通用代理、账户或凭据接口。请求只替换顶层 `model`，其他 JSON 数字、工具及缓存字段保留；SSE 和工具响应按收到的字节转发。

`claude-map <binding UUID>` helper 输出的是本 binding 的独立本地 bearer；真实推理 key 只由原生转发器从系统 Vault 取得，并发送到冻结的 HTTPS 节点。本地 token 与真实 key 均不进入 profile 或普通 SQLite。旧 `claude` helper 模式拒绝映射 binding。账户、安装、连接、节点、模型、key revision 和授权 epoch 均冻结于该 binding，旧 token 不能随当前连接切换而指向另一账户。

预览只保留临时端口，不接受推理。配置 journal 提交且绑定启用后才运行 HTTP 服务。退出 Orbit 会停止映射；关闭窗口而保留进程时可以继续。重开使用配置中的原端口，被占用时明确失败，不抢占或静默改配置。恢复原文件与恢复有效旧映射分别判断，退出、撤销及过期授权不会复活。映射在途状态参与更新忙碌门禁；进程退出或断线不能证明上游已停止或零费用。

启动时先认证映射上下文，再核对严格派生的 profile、当前选中条目和第三方模式。profile 保持完整字节核验；Claude 正常写入的其他偏好不阻止同一映射重开。三文件写入与恢复仍逐字节检查，偏好变化造成的事务冲突继续进入协调流程。

传输限制为最多 16 条连接、2 条上游请求，头 32 KiB、JSON 请求 8 MiB、累计响应 64 MiB。上游连接与本地收头各 10 秒，上游首响应与流空闲各 120 秒，单次转发最多 15 分钟。阻塞授权工作即使遇到客户端断连，也继续占用自己的并发额度直到结束。

映射对每个收到的请求最多发送一次上游请求，不自动重试、排队重发或重放结果。由适配器构造的终态响应设置 `x-should-retry: false`；Hyper 在进入适配器前拒绝的畸形 HTTP 保证没有上游发送，但不依赖自定义响应头。这不能证明 Claude SDK 在所有断流情况下都不重发；未确认的结果不能标为未执行或零费用。

旧无 mapping 字段的上下文保持原序列化字节和 `scope_revision`，新可选字段为空时省略；没有迁移或重写历史备份。角色映射仍沿用原三文件确认、加密 journal、冲突检查与恢复流程。配置预览必须显示实际模型、本机 URL 和 Orbit 需保持运行；首次真实应用映射前须重新确认。当前源码和合成检查不能代替真实 Code 载入、流式、工具与恢复验收。

本机 `4.4212.0` 的一次真实 Code Read 工具与随机文件返回已验证，原配置随后还原，详见[验证记录](validation.md)。首轮 helper 超时仍保留为限制；本次恢复包含单独的偏好协调和 metadata 权限补回，不构成自动合并外部变化或全部桌面功能的验收。

## 本阶段最少检查

- 合成配置库：扁平 profile、三文件顺序、未知字段保留、原选择恢复、秘密脱敏、大小和路径限制。
- 资格与 journal：管理/远端选择拒绝、目标晚变、三文件中断和重新进入、任一第三方状态整组停写、旧上下文拒绝、恢复不复活授权。
- Service 与界面：预览、确认、保存、重开和整组恢复；确认资格变化后旧预览永久失效；保存与载入、连接证据始终分离。
- 受影响的原生测试和 Mac 编译、前端类型/构建及相关浏览器测试。既有 Panel 授权通过证据不因本次 Claude 配置变更重复执行。
