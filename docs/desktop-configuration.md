# 桌面用户配置保存合同

2026-10-22 主线修正正在实施。此文定义本阶段的保存与恢复边界，测试、原生运行及候选证据仍须分别取得，不能据此声称已经验收。

当前生产配置目标收据仅适配固定版本的 macOS arm64 客户端。Windows 目标及相应 synthetic fixture 尚待适配；本阶段的 Mac 编译和测试不能代表 Windows 支持。

## 保存、载入和连接

Codex 的保存资格取决于受支持的已安装客户端、固定捆绑 CLI/profile、明确的用户配置目录和本地写入限制。保存前不要求客户端已启动；保存后仅报告“配置已保存、待重启”，运行来源、实际载入和连接状态继续单独记录。默认用户目录不是对当前运行实例使用 `CODEX_HOME` 或前台 host 的证明。

[OpenAI 官方网关说明](https://learn.chatgpt.com/docs/enterprise/connect-to-a-gateway)先配置用户文件，再重启桌面应用。[管理配置](https://learn.chatgpt.com/docs/enterprise/managed-configuration)区分用户默认值与强制要求；后者仍由客户端执行。Orbit 仅修改用户配置，不修改管理文件或远端策略。

## 写入资格与确认

全局 `managed` 保留 `yes/no/unknown` 的真实含义。Codex 另有用户文件写入资格：本地相关来源完整可判定且没有管理限制时为 `allowed`；已知管理限制为 `blocked`；缺覆盖、读取失败、格式或目标无法确认时为 `unverified`。任何已知的强制限制均不能用确认覆盖。远端组织策略未取得时仍为未知，预览明确提示它可能影响配置生效。

界面读取配置资格及摘要，不提供证明。预览绑定完整账户、安装、凭据、节点、模型目录、配置目标与本地策略；确认保存前重新检查。旧客户端视图缺少新字段时默认未核验。未知运行来源不能被标成已核验，也不充当保存权限。

## 文件与恢复

预览不创建默认目录。首次确认后，只允许在已核验的用户目录下创建固定 `.codex` 目录；不猜测其他根或创建任意路径。目标摘要绑定安装材料、配置合同和明确的目录作用域，排除目录修改时间及本次生成文件，避免自身写入使资格失效。

既有双文件 journal、加密备份、读回和外部修改冲突检查继续适用。沿用 v3 AEAD，在密文内加入版本为 1 的配置目标合同；旧运行来源上下文缺少此收据，不能自动取得新权限。Vault 返回后、每个文件写入前和授权启用前复查。恢复原字节不会复活已退出、撤销、过期或遗忘的授权。目录创建与文件、安全存储之间仍是可恢复流程，不承诺全局原子事务。

Claude 的独立文件与选择合同见 [Claude Desktop 本地配置合同](claude-configuration.md)。此 Codex 合同不授予 Claude 写入权限；各客户端仍分别核验目标、来源和恢复操作。
