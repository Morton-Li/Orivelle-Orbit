# 桌面接入配置

在 Orbit 登录后，打开「接入」，为客户端选择 Panel 授权的节点和模型。配置预览列出目标版本、路径、连接和脱敏差异。确认后 Orbit 写入该客户端的配置并启用对应的凭据 helper。实际推理由目标客户端发起。

## 自动配置目标

| 客户端 | 当前安装合同 | 用户配置 |
| --- | --- | --- |
| Codex Desktop | macOS arm64，Desktop `26.1013.40934` 和捆绑 CLI `0.163.0-alpha.10.2` | 在 `~/.codex/` 联合写入用户 `config.toml` 与 Orbit 模型目录 |
| Claude Desktop | macOS arm64，Desktop `4.4212.0` | 在 `~/Library/Application Support/Claude-3p/` 联合发布新 profile、配置库索引和模式设置 |

自动保存和恢复均需核验已安装的应用签名、固定安装材料及默认用户目录。Windows 有客户端检测和设备策略观察入口，自动写入资格目前只覆盖表中的目标。预览可检查尚未建立的默认目录，目录创建发生在确认后的受锁写入流程内。 [目标核验实现](../crates/orbit-core/src/system.rs)

Codex 在用户配置中使用独立 provider 和凭据 helper，CLI 和 IDE 可能共用这份配置。Claude 的第三方模式适用于整个 Desktop。 [Codex 配置和模型目录](codex-catalog.md) · [Claude 本地配置库](claude-configuration.md)

## 组织策略与写入资格

`managed` 描述组织策略观测。发现接管配置的策略时为 `yes`，只有覆盖完整且观测结果明确时才为 `no`，观测不足时为 `unknown`。当前远端组织策略缺少覆盖证明，因此即使本地来源已核对，远端组织策略仍未知，客户端启动时可能限制配置生效。

两个客户端各自判定本地写入资格 `configuration_access`。本地相关来源完整且允许用户配置、安装目标提示通过时显示 `allowed`。已知接管策略使资格为 `blocked`，本地来源覆盖不足、读取失败、格式不明或目标无法核对时为 `unverified`。卡片上的资格用于引导预览，执行权限由 Rust 根据完整安装目标和当前策略决定。

在 macOS 上，Codex 观察固定系统 requirements、旧 managed 文件和管理偏好域的两个 TOML 键。普通偏好有值但未经确认为强制时仍属未核验。Claude 观察机器和用户的 MDM plist，按固定版本的 schema 对各键执行两次强制状态检查。Windows 的观察范围包括 Codex 的固定策略文件及 Claude 的注册表策略元数据。界面仅接收状态和摘要，策略正文留在原生观测范围内。 [策略观察实现](../crates/orbit-core/src/policy.rs)

## 确认、重启和恢复

预览绑定账户、Panel、安装、连接、凭据、节点、模型、客户端目标、策略和文件状态。应用时重新检查上下文和实际文件，预览过期或其中任何依赖发生变化时须重新生成。写入和 helper 授权通过加密操作日志协调，配置文件读回通过后才启用新绑定。

保存、载入和连接是三个独立状态。保存后完整退出并重启对应客户端。配置文件读回确认保存结果，实际载入和连接由独立的客户端验证确认。 [验证范围](validation.md)

配置按操作组加密备份，每个客户端最多保留五组，每组最长三十天。在「接入」的备份区域选择原账户与 Panel，再为所选备份预览并确认恢复。退出账户后仍可用原安装身份和备份密钥恢复，客户端目标与当前策略须继续符合资格。文件有外部变更时整组停止覆盖。字节恢复与授权恢复分别检查，失效的 helper 授权保持禁用。忘记安装会失去对应备份的恢复能力。

启动时只协调经用户确认且上下文仍可验证的操作组。当前日志使用 AAD v3 绑定策略摘要，读取兼容 AAD v2。文件、安全存储和授权绑定以日志协调，外部进程的写入仍可能与最后一次检查竞争。 [配置事务实现](../crates/orbit-core/src/config.rs)
