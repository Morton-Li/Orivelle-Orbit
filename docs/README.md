## 维护约定

- README 面向使用者；`architecture/` 解释职责、数据流与安全边界；`development/` 维护可执行的开发与发布方法；`testing/` 维护验证入口、关键结果及未通过条件。
- 当前行为以源码和配置为准。固定日期的测试绑定当时源码、环境和替换组件，不代表当前候选、其他平台、发布包或生产服务已经通过。
- 功能变化优先更新已有主题与本索引；不为每轮开发新增阶段报告，不把临时演示端口、工作区、凭据或一次性授权写成永久前置条件。
- 删除旧文档前检查脚本/测试依赖，将独有决策、真实失败和未验证边界合入对应主题。原文通过 Git 历史查阅，不建立平行 archive；可执行夹具与独有回执继续保留在测试目录。
