# 更新与恢复

## 渠道与信任

默认构建的更新功能处于关闭状态。启用检查需要在编译时配置 HTTPS 渠道和固定 updater 公钥。客户端只接受同源制品，拒绝重定向、降级及签名版本不符的制品。安装使用本地重新验证的同一份字节。macOS 还会校验应用标识、版本、arm64 架构及配置的签名证书指纹。即使配置了更新渠道，Windows 自动安装仍会因恢复未验证而拒绝。

## macOS 更新事务

安装要求任务和修改已结束、配置 journal 处于可更新状态，并持有维护 lease 和 helper 独占锁。交换应用前生成一致的 SQLite 备份，记录原、新应用树和数据校验值。

`updates/pending.json` 在 SQLite 之外记录事务，绑定安装、目标版本、平台和操作 UUID。应用与操作路径由受信数据目录和当前 bundle 推导。GUI 先取得进程锁，再协调更新恢复，最后打开普通 Store。未完成或畸形事务会阻止普通启动和 helper 交付凭据。

| 状态 | 恢复行为 |
| --- | --- |
| `prepared` | 按应用树摘要判断交换是否发生。未交换时保留原应用和数据 |
| `validating` | 仅在私有数据库副本中核验 schema、完整性和元数据。提交中断时进入回退 |
| `rolling_back` | 依照持久化记录隔离数据库及 WAL/SHM，恢复旧数据和应用树 |
| `committed` | 正常启动，保留此后产生的数据 |
| `rolled_back` | 需要从旧应用启动，已载入新版二进制的进程停止 |
| `aborted` | 保留尚未交换的原应用和数据 |

恢复遇到不属于本事务的应用或数据库内容时停止覆盖。回退快照会清除活动连接、载入和连接证据，禁用会话与 helper 授权。系统安全存储中的秘密保留在快照之外。下一次更新可以按已核验的清单清理前次事务的终态材料，发现变更或新增文件时停止。

实现和故障夹具位于 [Orbit Core](../crates/orbit-core/src/update_recovery.rs)。真实安装、签名、升级和回退的状态见[验证指南](validation.md)。
