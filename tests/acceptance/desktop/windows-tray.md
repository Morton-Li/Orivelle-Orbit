# Windows 托盘快捷面板

日期：2026-11-14。分支：`feature/windows-tray-panel`，基于 macOS 菜单栏面板提交 `fd6b50e`。

## 实现

- 复用已实现的只读账户、用量、接入和任务汇总，保留账户切换隔离及隐藏时停止轮询。
- Windows 使用独立的紧凑样式：384 px 面板内容、10 px 圆角、无菜单栏尖角、Segoe UI 字体、带背景的底部操作区。浅色、深色和跟随系统继续读取 Orbit 设置。
- 单击托盘展开或收起；双击恢复已有主窗口，屏蔽 Win32 双击后最后一次 mouse-up，避免重新弹出面板。右键保持原生菜单，失焦、Esc、关闭请求与页面导航收起面板。
- 窗口不进入任务栏，关闭面板不退出服务。面板无法创建时保留主窗口入口。
- 点击时保存 Shell 提供的图标位置，避免隐藏图标区收起后重新布局失去锚点。按该屏幕的工作区选择上、下、左、右展开方向，并约束在工作区内。
- 使用目标屏幕的物理坐标及尺寸放置窗口，避免跨不同 DPI 屏幕时使用窗口原来的缩放倍数。
- Windows 和 macOS 使用同一项受限窗口能力，不向面板开放图片提交、客户端配置或设置修改权限。

## 本地验证

- `npm run check`：格式、lint、类型、167 项单元测试、生产构建和测试夹具排除检查通过。
- `npm run test:e2e -- --reporter=line`：36 项通过。新增 Windows UA 测试检查浅色、深色、无尖角、导航、Esc 和窄容器；原有 macOS 面板回归也通过。
- 桌面 Rust 库 8 项测试通过。其中新增 Windows 定位测试覆盖四种任务栏方向、隐藏图标区、负坐标副屏、150% 缩放和较矮的工作区。
- macOS 目标的 `cargo check --locked --offline -p orivelle-orbit --features native-acceptance` 通过，确认原生验收构建分支仍可编译；这不是 Windows 目标构建。
- 本地 Rust 使用已有的 1.98.0 编译器；项目固定的 1.97.1 未改动。
- 浏览器截图位于 `test-results/menubar-Windows-tray-panel-*/windows-tray-{light,dark}.png`，已查看两种主题的实际应用组件渲染。它们使用测试账户数据，不是 Windows 系统桌面截图。

## Windows 原生验证边界

当前本机为 macOS，已授权的 lab.lan 为 Ubuntu；没有在本次工作中使用 Windows 原生环境。因此 Windows MSVC 目标构建、WebView2、实际托盘鼠标事件、全屏及真实多屏 DPI 行为仍待 Windows 环境验证，不能用浏览器 UA 或纯定位测试替代。

已有 `Windows Integration` 工作流的原生脚本已扩展，但本次没有推送代码或触发该工作流：

- 除了主窗口，识别独立的面板 HWND，读取其可见性、前台焦点、工作区边界和 tool-window 标记。
- 通过 Windows Shell 获取图标位置并真实单击，检查浅深主题与账户状态同步。
- 通过键盘 Esc 和切回主窗口检查关闭，通过面板入口检查复用原主窗口。
- 调用受限面板无法获得的图片提交命令，检查 ACL 拒绝。
- 原有双击恢复测试增加面板仍然隐藏的断言。
- 调整 CDP 目标选择，避免预加载的独立面板被当作主窗口。

后续原生验收须使用包含本次应用代码的新构建；旧安装包不能作为本次实现的验证。全屏、固定可见的托盘图标反复切换、隐藏图标区以及 100%/150%/200% 真实多屏仍需系统环境补测。
